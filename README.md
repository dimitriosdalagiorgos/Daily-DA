# Πλατφόρμα δήλωσης και κατανομής ομίλων

Διαδικτυακή πλατφόρμα για τους **ομίλους** ενός σχολείου: οι γονείς δηλώνουν με σειρά προτίμησης τους ομίλους κάθε ημέρας, οι εκπαιδευτικοί ορίζουν (προαιρετικά) μαθητές που προτιμούν, και η κατανομή γίνεται αυτόματα με τον αλγόριθμο **αναβαλλόμενης αποδοχής (Deferred Acceptance)**, με επαληθεύσιμη κλήρωση και πλήρες ημερολόγιο αποφάσεων. Η ίδια κατανομή τρέχει και **offline σε R**, με ταυτόσημα αποτελέσματα.

Αναπτύχθηκε για το **ΔΗΜ.Ω.Σ. – Ημερήσιο Γενικό Λύκειο Κοζάνης** και διατίθεται ελεύθερα (άδεια MIT) σε κάθε Δημόσιο Ωνάσειο Σχολείο — ή οποιοδήποτε σχολείο — που θέλει να τη χρησιμοποιήσει.

> **Χωρίς υποστήριξη.** Ο κώδικας δίνεται «ως έχει». Ο δημιουργός δεν μπορεί να εξυπηρετήσει άλλα σχολεία· την εγκατάσταση και τη λειτουργία την αναλαμβάνει ο υπεύθυνος πληροφορικής (IT) κάθε σχολείου, με τις οδηγίες αυτού του αρχείου.

### Για άλλα σχολεία, με μια ματιά

1. **Πάρτε δικό σας αντίγραφο:** κουμπί **Fork** πάνω δεξιά (§5.1). Το fork είναι δικό σας· ό,τι αλλάζετε εκεί **δεν** επηρεάζει αυτό το αποθετήριο, και κανείς άλλος δεν μπορεί να αλλάξει το δικό σας.
2. **Διαλέξτε πού θα τρέχει** (§4): Netlify + Supabase (μόνο ρυθμίσεις σε ιστοσελίδες) ή δικός σας Linux server.
3. **Ετοιμάστε τα αρχεία του σχολείου** (§3): κατάλογος myschool και το πρότυπο ομίλων.
4. **Πρώτη χρήση** (§7) και, για κάθε ρόλο, τα εγχειρίδια (§2).

Σφάλματα ή προτάσεις: **Issues** αυτού του αποθετηρίου. Ο κώδικας εδώ αλλάζει μόνο από τον δημιουργό του.

## 1. Τι κάνει η πλατφόρμα

**Τρεις ρόλοι, ο καθένας στη δική του διεύθυνση** — χωρίς συνδέσμους από τη μία σελίδα στην άλλη: οι γονείς στην κεντρική διεύθυνση, οι εκπαιδευτικοί και ο διαχειριστής σε κρυφές διευθύνσεις που ορίζονται εκτός κώδικα (`TEACHER_PATH`, `ADMIN_PATH`, βλ. παρακάτω). Η κρυφή διεύθυνση δεν αντικαθιστά τον κωδικό: κάθε σελίδα ζητά τον δικό της.

| Ρόλος | Σύνδεση | Τι κάνει |
|---|---|---|
| **Διαχειριστής** (υπεύθυνος ομίλων) | κωδικός διαχείρισης | Ανεβάζει κατάλογο μαθητών (myschool) και αρχείο ομίλων, ορίζει ρυθμίσεις και προθεσμίες, αλλάζει φάσεις, τρέχει την κατανομή, κατεβάζει αποτελέσματα και αναφορές. |
| **Εκπαιδευτικός** | κοινός κωδικός εκπαιδευτικών (τον ορίζει ο διαχειριστής) + ΑΜ ή ΑΦΜ του (στήλη του αρχείου ομίλων· αποθηκεύεται μόνο ως κρυπτογραφικό αποτύπωμα) — βλέπει μόνο τους ομίλους του· ή προσωπικός σύνδεσμος | Ορίζει, αν θέλει, μαθητές που προτιμά (τη χωρητικότητα την ορίζει ο διαχειριστής). Εναλλακτικά συμπληρώνει Excel που του δίνει ο διαχειριστής. |
| **Γονέας** | κοινός κωδικός γονέων + ΑΜ και ονόματα μαθητή | Βάζει σε σειρά τους ομίλους κάθε ημέρας, παίρνει απόδειξη, βλέπει το αποτέλεσμα και πώς προέκυψε. |

**Φάσεις:** Προετοιμασία → Εκπαιδευτικοί → Δηλώσεις γονέων → Κλειστές δηλώσεις → Κατανομή → Ανακοίνωση.

**Κατανομή:** ημέρα-ημέρα (Δευτέρα → Παρασκευή), με υποστήριξη ομίλων που γίνονται δύο ή τρεις ημέρες, τάξεων με υποχρεωτική ένταξη, λιστών εκπαιδευτικών και κλήρωσης από δημοσιευμένο seed. Εξήγηση: [docs/algorithm.md](docs/algorithm.md).

**Offline σε R:** ο φάκελος [`R/`](R/) κάνει την ίδια κατανομή στον υπολογιστή του υπευθύνου, από τα δεδομένα που εξάγει η πλατφόρμα — για επαλήθευση ή αν η πλατφόρμα δεν είναι διαθέσιμη. Σε κάθε αλλαγή του κώδικα ελέγχεται αυτόματα ότι πλατφόρμα και R δίνουν ταυτόσημα αποτελέσματα.

## 3. Τι πρέπει να ετοιμάσει το σχολείο

Πριν από οποιαδήποτε εγκατάσταση, ο υπεύθυνος ομίλων χρειάζεται:

1. **Κατάλογο μαθητών από το myschool:** «Κατάλογος Μαθητών» σε Excel (.xls), όπως εξάγεται — με τάξη, ΑΜ, επώνυμο, όνομα, όνομα πατέρα, όνομα μητέρας. Η πλατφόρμα τον διαβάζει όπως είναι.
2. **Προαιρετικά, τα τμήματα των μαθητών:** οι αναφορές «Γενικά Στοιχεία Τμημάτων» και «Τμήματα μαθητών» του myschool σε CSV. Από αυτές η πλατφόρμα κρατά μόνο το τμήμα Γενικής Παιδείας (π.χ. Α1), για τους πίνακες και τα παρουσιολόγια.
3. **Αρχείο ομίλων:** το πρότυπο [`platform/templates/omiloi_protypo.xlsx`](platform/templates/omiloi_protypo.xlsx) συμπληρωμένο: κωδικός, όνομα, ημέρα/ημέρες, τάξεις, χωρητικότητα, περιγραφή, προαιρετικά «Παρεμφερείς» (όμιλοι διαφορετικών ημερών από τους οποίους κάθε μαθητής παίρνει το πολύ έναν), και σε δεύτερο φύλλο οι εκπαιδευτικοί κάθε ομίλου με το email τους και τον **ΑΜ** (μόνιμοι) ή το **ΑΦΜ** τους (αναπληρωτές) — με αυτόν συνδέονται, μαζί με τον κοινό κωδικό εκπαιδευτικών.
4. **Αποφάσεις του σχολείου:**
   - ποιες τάξεις έχουν **υποχρεωτική ένταξη** σε όμιλο·
   - **προθεσμίες** για εκπαιδευτικούς και γονείς·
   - τον **κοινό κωδικό γονέων** (ανακοινώνεται στους γονείς) και τα **στοιχεία επικοινωνίας** που θα βλέπουν·
   - τον **κοινό κωδικό εκπαιδευτικών** (μπορεί να είναι και ίδιος με των γονέων)·
   - πώς θα ορίσει το **seed της κλήρωσης** (π.χ. αριθμοί που κληρώνονται δημόσια, μετά το κλείσιμο των δηλώσεων).
4. **Διεύθυνση (domain)** για την πλατφόρμα, αν δεν αρκεί η δωρεάν διεύθυνση του Netlify.

Τα πραγματικά αρχεία μαθητών **δεν** μπαίνουν ποτέ στο GitHub· ανεβαίνουν μόνο στην πλατφόρμα, από τον διαχειριστή.

## 5. Εγκατάσταση Α: Netlify + Supabase

Οι ονομασίες των μενού μπορεί να διαφέρουν λίγο, καθώς οι υπηρεσίες ανανεώνουν τις σελίδες τους.

### 5.1. Αντίγραφο του κώδικα

1. Λογαριασμός στο https://github.com.
2. Σε αυτό το αποθετήριο: **Fork** (πάνω δεξιά) → δημιουργείται αντίγραφο στον λογαριασμό σας. Αν θέλετε, κάντε το αντίγραφο **ιδιωτικό** (Settings → General → Danger Zone → Change visibility)· η πλατφόρμα λειτουργεί το ίδιο.
3. (Προαιρετικά) Στο fork σας, καρτέλα **Actions** → ενεργοποιήστε τα workflows, ώστε κάθε δική σας αλλαγή να ελέγχεται αυτόματα (tests, σύγκριση με το R, διαδρομή σε browser). Στα forks είναι απενεργοποιημένα αρχικά.

### 5.2. Βάση δεδομένων (Supabase)

1. Λογαριασμός στο https://supabase.com → **New project**.
2. Όνομα (π.χ. `omiloi`), κωδικός βάσης (φυλάξτε τον), **Region: Europe — Frankfurt** (ή άλλη περιοχή της ΕΕ).
3. Όταν ετοιμαστεί: **SQL Editor** → **New query** → επικολλήστε ολόκληρο το [`platform/supabase/schema.sql`](platform/supabase/schema.sql) → **Run**. Δημιουργούνται δύο πίνακες (`kv`, `log`) προσβάσιμοι μόνο από τον διακομιστή της πλατφόρμας.
4. Σημειώστε:
   - **Project URL** (Project Settings → Data API, ή API): μοιάζει με `https://abcdefgh.supabase.co`·
   - **Secret key** (Project Settings → API Keys): το **μυστικό** κλειδί — όχι το «publishable/anon».

### 5.3. Ιστότοπος (Netlify)

1. Λογαριασμός στο https://netlify.com (π.χ. με τον λογαριασμό GitHub).
2. **Add new project → Import an existing project → GitHub** → επιλέξτε το αντίγραφό σας, κλάδος (branch) **`main`**. Οι ρυθμίσεις build διαβάζονται αυτόματα από το [`netlify.toml`](netlify.toml)· μην αλλάξετε τίποτα.
3. **Project configuration → Environment variables** → προσθέστε:

   | Μεταβλητή | Τιμή |
   |---|---|
   | `SUPABASE_URL` | το Project URL |
   | `SUPABASE_SECRET_KEY` | το Secret key |
   | `ADMIN_PASSWORD` | κωδικός διαχείρισης, **τουλάχιστον 10 χαρακτήρες** |
   | `TEACHER_PATH` | κρυφή διεύθυνση της σελίδας εκπαιδευτικών, 8–64 λατινικοί χαρακτήρες/ψηφία/`-`, π.χ. `e-7kq3m9xa` → `https://<διεύθυνση>/e-7kq3m9xa/` |
   | `ADMIN_PATH` | κρυφή διεύθυνση της σελίδας διαχείρισης, π.χ. `d-x82pfa4q` (διαφορετική από την προηγούμενη) |

   Τις δύο διευθύνσεις τις χρειάζονται και το build και το API· χωρίς αυτές το build σταματά. Διαλέξτε τυχαίους χαρακτήρες (όχι λέξεις) και αλλάξτε τις αν διαρρεύσουν (νέα δημοσίευση).

4. **Deploys → Trigger deploy → Deploy site.** Σε 1–2 λεπτά η πλατφόρμα είναι στη διεύθυνση `https://<όνομα>.netlify.app` (το όνομα αλλάζει στο Project configuration → General). Δικό σας domain: **Domain management**.
5. Έλεγχος: ανοίξτε `https://<διεύθυνση>/api/public` — πρέπει να δείτε κείμενο που αρχίζει με `{"phase":"setup"`.

**Δημοσίευση μόνο όταν τη ζητάτε.** Το [`netlify.toml`](netlify.toml) έχει κανόνα `ignore`: μια αλλαγή στο GitHub δημοσιεύεται **μόνο αν** κάποιο από τα νέα commits έχει στο μήνυμά του τη λέξη `[deploy]`. Τα υπόλοιπα «παραλείπονται» (Skipped) και δεν καταναλώνουν credits. Για χειροκίνητη δημοσίευση: Netlify → **Deploys → Trigger deploy → Deploy site**. Για δημοσίευση σε κάθε αλλαγή, διαγράψτε τη γραμμή `ignore` από το `netlify.toml`.

**Credits του Netlify.** Στο δωρεάν πρόγραμμα κάθε δημοσίευση καταναλώνει credits· αν τελειώσουν, οι δημοσιεύσεις σταματούν μέχρι τον επόμενο μήνα και, σε ακραία περίπτωση, ο ιστότοπος αναστέλλεται. Ενημερώνετε λοιπόν τον κώδικα **σπάνια** (π.χ. μία φορά πριν την έναρξη της χρονιάς) και ελέγξτε τα όρια του προγράμματός σας πριν την περίοδο των δηλώσεων.

## 6. Εγκατάσταση Β: δικός σας Linux server (Debian / Ubuntu)

Κατάλληλη αν το σχολείο έχει ήδη μηχάνημα προσβάσιμο από το internet (π.χ. το VM του καταλόγου βιβλιοθήκης). Η πλατφόρμα είναι μικρή (20–60 MB μνήμης, λίγα MB στον δίσκο) και **δεν χρειάζεται βάση δεδομένων**: τα δεδομένα κρατιούνται σε ένα αρχείο.

**Προϋποθέσεις:**

- πρόσβαση με `sudo`·
- ένα όνομα (π.χ. `omiloi.<σχολείο>.gr`) που δείχνει στο μηχάνημα· το ζητάτε από όποιον διαχειρίζεται το domain του σχολείου·
- Apache (ή nginx) για το HTTPS·
- ανοιχτές προς το internet **μόνο** οι θύρες 22 (SSH), 80 και 443. Σε cloud (π.χ. nefos.sch.gr) αυτό ρυθμίζεται συνήθως στις «Ομάδες ασφαλείας» (security groups)·
- **η έγκριση του υπευθύνου του μηχανήματος:** θα φιλοξενεί προσωπικά δεδομένα μαθητών.

Αν το μηχάνημα τρέχει ήδη άλλες υπηρεσίες (π.χ. Koha), διαβάστε **πρώτα** την §6.8.

### 6.1. Node.js 22

```sh
sudo apt update && sudo apt install -y git curl
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node --version        # πρέπει να δείξει v22.x
```

Χρειάζεται Node.js 20 ή νεότερο· η έκδοση των αποθετηρίων του Debian 12 είναι παλαιότερη. Με το NodeSource οι ενημερώσεις ασφαλείας του Node.js έρχονται μαζί με τις υπόλοιπες του συστήματος (`apt upgrade`).

**Με λίγο χώρο στον δίσκο** (π.χ. κάτω από 1 GB ελεύθερο): αντί για τα παραπάνω, εγκαταστήστε μόνο το πρόγραμμα `node` (~120 MB, χωρίς `npm`, που δεν χρειάζεται), με έλεγχο γνησιότητας:

```sh
cd /tmp
URL=https://nodejs.org/dist/latest-v22.x
case $(uname -m) in x86_64) ARCH=x64 ;; aarch64) ARCH=arm64 ;; *) ARCH=unsupported ;; esac
FILE=$(curl -fsSL $URL/SHASUMS256.txt | grep -o "node-v22\.[0-9.]*-linux-$ARCH\.tar\.xz" | head -1)
[ -n "$FILE" ] && curl -fSLO "$URL/$FILE" \
 && curl -fsSL $URL/SHASUMS256.txt | grep " $FILE\$" | sha256sum -c - \
 && sudo tar -xJf "$FILE" -C /usr/local/bin --strip-components=2 --no-same-owner "${FILE%.tar.xz}/bin/node" \
 && sudo chmod 755 /usr/local/bin/node
rm -f "/tmp/$FILE"; cd ~
/usr/local/bin/node --version
```

- Το `sha256sum -c` πρέπει να γράψει `OK` (ή `ΕΝΤΑΞΕΙ`)· αλλιώς δεν εγκαθίσταται τίποτα.
- Επιλέγει μόνο του το αρχείο για τον επεξεργαστή του μηχανήματος (x86-64 ή ARM64)· σε άλλους επεξεργαστές δεν εγκαθίσταται τίποτα.
- Στην §6.4 το `ExecStart` γίνεται `/usr/local/bin/node --max-old-space-size=80 server/start.mjs`.
- Αυτό το Node.js **δεν ενημερώνεται μόνο του:** για νέα έκδοση ξανατρέχετε το ίδιο μπλοκ και μετά `sudo systemctl restart omiloi`.

### 6.2. Κώδικας, χρήστης και φάκελος δεδομένων

```sh
sudo adduser --system --group --home /opt/omiloi omiloi
sudo GIT_TERMINAL_PROMPT=0 git clone --depth 1 --single-branch --branch main \
  https://github.com/dimitriosdalagiorgos/Daily-DA.git /opt/omiloi/app
sudo mkdir -p /var/lib/omiloi
sudo chown omiloi:omiloi /var/lib/omiloi
sudo chmod 700 /var/lib/omiloi
```

- Ο χρήστης `omiloi` δεν μπορεί να συνδεθεί και γράφει **μόνο** στο `/var/lib/omiloi`. Ο κώδικας ανήκει στον root.
- `--depth 1`: μόνο η τελευταία έκδοση, χωρίς το ιστορικό (λίγα MB). Το `GIT_TERMINAL_PROMPT=0` κάνει την εντολή να αποτύχει αντί να ζητήσει κωδικό, αν το αποθετήριο είναι ιδιωτικό.
- Αν χρησιμοποιείτε δικό σας fork, αλλάξτε τη διεύθυνση του `git clone`.

Έλεγχος ότι ο κώδικας είναι πλήρης (περιμένετε το μήνυμα «✗ Ορίστε ADMIN_PASSWORD…», που εδώ σημαίνει επιτυχία):

```sh
cd /opt/omiloi/app/platform && sudo -u omiloi node server/start.mjs; cd ~
```

```sh
sudo nano /etc/omiloi.env
```

```ini
TEACHER_PATH=e-7kq3m9xa
ADMIN_PATH=d-x82pfa4q
DATA_DIR=/var/lib/omiloi
PORT=3100
HOST=127.0.0.1
```

- `ADMIN_PASSWORD`: τουλάχιστον 10 χαρακτήρες. Αποφύγετε κενά, εισαγωγικά, `\` και `$`, που μπερδεύουν το systemd.
- `BASE_URL`: η δημόσια διεύθυνση (χρησιμοποιείται στους συνδέσμους των εκπαιδευτικών).
- `TEACHER_PATH`, `ADMIN_PATH`: οι κρυφές διευθύνσεις των σελίδων εκπαιδευτικών και διαχείρισης (8–64 λατινικοί χαρακτήρες, ψηφία, `-` ή `_`, διαφορετικές μεταξύ τους). Αν έχετε και εγκατάσταση στο Netlify, μπορείτε να βάλετε τις ίδιες.
- `PORT`: οποιαδήποτε ελεύθερη θύρα· `HOST=127.0.0.1`: η πλατφόρμα ακούει **μόνο τοπικά** και τη βλέπει μόνο ο Apache/nginx. Προσοχή σε μηχάνημα με Koha: η θύρα 8080 χρησιμοποιείται συχνά από το Koha — γι' αυτό εδώ 3100.
- Αργότερα αλλάζετε μία τιμή με `sudo nano /etc/omiloi.env` και μετά `sudo systemctl restart omiloi`. **Μην ξαναγράφετε ολόκληρο το αρχείο** με εντολή: θα χάνονταν οι υπόλοιπες ρυθμίσεις.
- Το αρχείο **δεν** μπαίνει ποτέ στο GitHub και το περιεχόμενό του δεν στέλνεται σε κανέναν. Για να το δείτε χωρίς τον κωδικό: `sudo grep -v '^ADMIN_PASSWORD' /etc/omiloi.env`.

### 6.4. Αυτόματη εκκίνηση (systemd)

```sh

```

```ini
[Unit]

After=network.target

[Service]
User=omiloi
Group=omiloi
WorkingDirectory=/opt/omiloi/app/platform
EnvironmentFile=/etc/omiloi.env

ProtectHome=true

[Install]

```

- `MemoryMax=128M`, `--max-old-space-size=80`: η πλατφόρμα δεν παίρνει ποτέ πάνω από 128 MB· αν τα ξεπεράσει, το systemd την ξαναξεκινά.
- `OOMScoreAdjust=500`: αν τελειώσει η μνήμη του μηχανήματος, θυσιάζεται **πρώτη** η πλατφόρμα και όχι η βάση δεδομένων ή άλλες υπηρεσίες.
- `Nice=5`: οι υπόλοιπες υπηρεσίες έχουν προτεραιότητα στον επεξεργαστή.
- Οι γραμμές `Protect…`, `Private…`, `ReadWritePaths`: η πλατφόρμα μπορεί να γράψει μόνο στο `/var/lib/omiloi`.
- Με το Node.js της §6.1 «με λίγο χώρο»: `ExecStart=/usr/local/bin/node …`.


### 6.5. Δημόσια πρόσβαση με HTTPS (Apache)

Ο Apache παίρνει μόνος του δωρεάν πιστοποιητικό από το Let's Encrypt και το ανανεώνει αυτόματα, με το ενσωματωμένο `mod_md` (Apache 2.4.30 και νεότερος· δεν χρειάζεται certbot). Πριν ξεκινήσετε, το όνομα πρέπει να δείχνει στο μηχάνημα: `getent hosts omiloi.example.gr`.

```sh
sudo a2enmod proxy proxy_http headers ssl md
sudo nano /etc/apache2/sites-available/omiloi.conf
```

```apache
# Πλατφόρμα ομίλων: HTTPS (Let's Encrypt μέσω mod_md) και προώθηση στο 127.0.0.1:3100.
MDCertificateAgreement accepted
MDContactEmail admin@example.gr
MDRequireHttps temporary
MDomain omiloi.example.gr

<VirtualHost *:80>
   ServerName omiloi.example.gr
</VirtualHost>

<VirtualHost *:443>
   ServerName omiloi.example.gr
   SSLEngine on
   ProxyPreserveHost On
   ProxyPass        / http://127.0.0.1:3100/
   ProxyPassReverse / http://127.0.0.1:3100/
   RequestHeader set X-Forwarded-Proto "https"
   ErrorLog  ${APACHE_LOG_DIR}/omiloi-error.log
   CustomLog ${APACHE_LOG_DIR}/omiloi-access.log combined
</VirtualHost>
```

- `MDContactEmail`: ένα email επικοινωνίας για το Let's Encrypt (χωρίς αυτό το πιστοποιητικό **δεν** εκδίδεται).
- `MDRequireHttps temporary`: όποιος ανοίγει `http://` μεταφέρεται στο `https://`. Όταν όλα δουλεύουν για μερικές εβδομάδες, μπορεί να γίνει `permanent`.
- Οι τρεις πρώτες γραμμές `MD…` ισχύουν για όλο τον Apache. Αν υπάρχουν ήδη σε άλλο αρχείο του μηχανήματος, εδώ αρκεί η γραμμή `MDomain`.
- Ένα νέο `VirtualHost` με δικό του `ServerName` δεν επηρεάζει τους υπόλοιπους ιστότοπους του μηχανήματος (π.χ. το Koha). Αν όμως το μηχάνημα δεν είχε ως τώρα HTTPS, δείτε την §6.8.

```sh
sudo apache2ctl configtest            # «Syntax OK» — αλλιώς μη συνεχίσετε
sudo a2ensite omiloi
sudo systemctl reload apache2
```

Σε 1–2 λεπτά το αρχείο καταγραφής γράφει ότι το πιστοποιητικό είναι έτοιμο (`AH10059 … has been setup`). Τότε ένα ακόμη ήπιο reload το ενεργοποιεί:

```sh
sudo grep -h '\[md:' /var/log/apache2/error.log | tail -3
sudo systemctl reload apache2
curl -s https://omiloi.example.gr/api/public   # {"phase":"setup",…}
```

- Μέχρι να ενεργοποιηθεί, το `https://` απαντά «503», σκόπιμα.
- Αν δείτε «No contact information», λείπει το `MDContactEmail`.
- Οι ανανεώσεις ενεργοποιούνται στο επόμενο reload του Apache· στο Debian γίνεται ήδη ένα κάθε μέρα, με την περιστροφή των αρχείων καταγραφής (`/etc/logrotate.d/apache2`).

Με **nginx** αντί για Apache, αντίστοιχα: `location / { proxy_pass http://127.0.0.1:3100; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto https; }` και `sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx -d omiloi.example.gr`. Το certbot μπορεί να χρησιμοποιηθεί και με τον Apache (`python3-certbot-apache`, `certbot --apache`), αν το προτιμάτε από το `mod_md`.

### 6.6. Αντίγραφα ασφαλείας

Όλα τα δεδομένα είναι στο `/var/lib/omiloi/store.json`. Ένα αντίγραφο κάθε νύχτα, ένα για κάθε ημέρα της εβδομάδας (`omiloi-1.json` = Δευτέρα … `omiloi-7.json` = Κυριακή, άρα κρατιούνται 7):

```sh
printf '%s\n' '15 2 * * * root [ -f /var/lib/omiloi/store.json ] && install -m 600 /var/lib/omiloi/store.json /var/backups/omiloi-$(date +\%u).json' \
  | sudo tee /etc/cron.d/omiloi-backup >/dev/null
sudo chmod 644 /etc/cron.d/omiloi-backup
```

- Το `%u` (αριθμός ημέρας) δεν εξαρτάται από τη γλώσσα του συστήματος, σε αντίθεση με το `%a`.
- **Επαναφορά:** `sudo systemctl stop omiloi`, `sudo install -m 600 -o omiloi -g omiloi /var/backups/omiloi-3.json /var/lib/omiloi/store.json` (το αντίγραφο της ημέρας που θέλετε), `sudo systemctl start omiloi`.
- Τα αντίγραφα είναι στον ίδιο δίσκο. Κρατάτε και ένα **εκτός μηχανήματος** στα σημαντικά σημεία της χρονιάς (π.χ. μετά το κλείσιμο των δηλώσεων και μετά την κατανομή), φυλαγμένο ασφαλώς: περιέχει προσωπικά δεδομένα. Σε cloud, ένα **snapshot του δίσκου** πριν από μεγάλες αλλαγές βοηθά επίσης.

### 6.8. Μηχάνημα που τρέχει ήδη Koha (ή άλλες υπηρεσίες)

Η πλατφόρμα είναι μικρή, αλλά το μηχάνημα μπορεί να είναι ήδη στο όριο. Ένα Koha 26.05 με MariaDB, RabbitMQ, Zebra, Plack και background workers πιάνει στην πράξη **1,8 GB μνήμης**. Σε VM με 2 GB μνήμης και χωρίς swap τελείωσε η μνήμη και σταμάτησε το Koha. Ελέγξτε πρώτα (μόνο ανάγνωση):

```sh
df -h /                                   # ελεύθερος χώρος: θέλετε τουλάχιστον 1 GB
free -m                                   # «available»: θέλετε αρκετές εκατοντάδες MB
sudo swapon --show                        # κενό = χωρίς swap
sudo ss -ltn                              # ποιες θύρες είναι πιασμένες (διαλέξτε ελεύθερη για το PORT)
sudo apache2ctl -S                        # οι ιστότοποι του Apache: δεν τους αγγίζετε
```

**Χώρος στον δίσκο**, ασφαλείς καθαρισμοί:

- `sudo apt-get clean`: σβήνει αντίγραφα πακέτων που έχουν ήδη εγκατασταθεί (μπορεί να είναι εκατοντάδες MB)·
- `sudo journalctl --vacuum-size=50M` και, μόνιμα, `SystemMaxUse=100M` σε ένα αρχείο στο `/etc/systemd/journald.conf.d/`·
- παλιοί πυρήνες: `dpkg -l 'linux-image-*'` και `uname -r`· όσοι **δεν** είναι ο τρέχων φεύγουν με `sudo apt-get purge linux-image-<έκδοση>`·
- πολύ μεγάλο `/var/log/auth.log`: ελέγξτε αν το SSH έχει μείνει σε κατάσταση αποσφαλμάτωσης (`sudo sshd -T | grep -i loglevel`)· η κανονική τιμή είναι `INFO`.

**Μνήμη:**

- Για Koha και πλατφόρμα μαζί, προτιμήστε **4 GB**. Σε cloud η μνήμη συχνά δεν αυξάνεται στο ίδιο instance: φτιάχνεται νέο instance από τον ίδιο δίσκο, αφού πάρετε snapshot.
- Swap χωρίς χρήση δίσκου (συμπιεσμένο στη μνήμη):

    ```sh
    sudo apt-get install -y zram-tools
    printf 'ALGO=zstd\nPERCENT=25\nPRIORITY=100\n' | sudo tee /etc/default/zramswap
    sudo systemctl restart zramswap && sudo apt-get clean
    ```

- Το Koha να μη σβήνει ολόκληρο όταν ο πυρήνας σταματήσει έναν εργάτη του για να ελευθερώσει μνήμη (η προεπιλογή του systemd σταματά όλη την υπηρεσία, και το Koha δεν ξεκινά ξανά μόνο του):

    ```sh
    sudo mkdir -p /etc/systemd/system/koha-common.service.d
    printf '[Service]\nOOMPolicy=continue\n' | sudo tee /etc/systemd/system/koha-common.service.d/oom.conf
    sudo systemctl daemon-reload
    ```

**HTTPS:** αν οι ιστότοποι του Koha είχαν μόνο `http://`, με το `ssl` ενεργό ο Apache αρχίζει να ακούει και στη θύρα 443, και όποιος γράψει `https://` στη διεύθυνση του Koha βλέπει προειδοποίηση πιστοποιητικού. Αυτό διορθώνεται με HTTPS και για το Koha, με τον ίδιο τρόπο: ένα `MDomain` με τα ονόματα του Koha και, σε **χωριστό** αρχείο, αντίγραφα των ιστότοπων του Koha για `<VirtualHost *:443>` με `SSLEngine on` και `RequestHeader set X-Forwarded-Proto "https"`. Το αρχείο του Koha (`/etc/apache2/sites-available/<instance>.conf`) δεν αλλάζει. Μετά, στο Koha, συμπληρώστε `OPACBaseURL` και `staffClientBaseURL` με `https://…`.

**Θύρες:** σε τέτοια μηχανήματα η βάση (3306) και το RabbitMQ (5672, 61613, 25672, 4369) συχνά ακούν σε όλες τις διευθύνσεις. Βεβαιωθείτε ότι το τείχος προστασίας ή οι «Ομάδες ασφαλείας» του cloud τις κρατούν **κλειστές** από το internet.

## 7. Πρώτη χρήση και ετήσια ροή

1. Ανοίξτε `https://<διεύθυνση>/<ADMIN_PATH>/` και συνδεθείτε με το `ADMIN_PASSWORD`.
2. **Πορεία & ρυθμίσεις:** όνομα σχολείου, επικοινωνία, τάξεις με υποχρεωτική ένταξη, κοινός κωδικός γονέων, κοινός κωδικός εκπαιδευτικών, προθεσμία. Η κάρτα «Διευθύνσεις» δείχνει ποια διεύθυνση δίνετε σε ποιους.
3. **Αρχεία:** κατάλογος μαθητών του myschool και αρχείο ομίλων. Η κάρτα «Έλεγχοι θέσεων» πρέπει να είναι πράσινη πριν ανοίξουν οι δηλώσεις.
4. Φάσεις: Εκπαιδευτικοί (διεύθυνση + κοινός κωδικός, ή προσωπικοί σύνδεσμοι από την καρτέλα «Όμιλοι») → Δηλώσεις γονέων → Κλειστές → Κατανομή (seed) → Ανακοίνωση.
5. **Στο τέλος της χρονιάς:** κατεβάστε ό,τι χρειάζεται να κρατήσει το σχολείο (αποτελέσματα, audit log, δεδομένα για R) και κάντε **Επαναφορά πλατφόρμας** (Πορεία & ρυθμίσεις → γράφετε ΔΙΑΓΡΑΦΗ): σβήνονται μαθητές, όμιλοι, δηλώσεις, αποτελέσματα και ιστορικό.

Αναλυτικά βήματα: καρτέλα **«Βοήθεια»** της σελίδας διαχείρισης.

**Ερωτήσεις γονέων** («γιατί μπήκε εκείνος και όχι το παιδί μου;»): «Κατανομή» → **«Κλήρωση: ΑΜ και αριθμός (.csv)»** δίνει τον αριθμό κλήρωσης κάθε μαθητή, ταξινομημένο κατά ΑΜ (μικρότερος αριθμός προηγείται στην ίδια προτεραιότητα)· η **«Αναφορά μαθητή»** δείχνει βήμα-βήμα τις αιτήσεις, αποδοχές και απορρίψεις ενός μαθητή, με την αιτία.

**Δοκιμή πριν τη χρονιά:** στην καρτέλα «Αρχεία» μπορείτε να εισαγάγετε περσινές δηλώσεις (ένα αρχείο ανά ημέρα), να τρέξετε δοκιμαστική κατανομή και μετά να κάνετε επαναφορά.

**Email (προαιρετικά).** Χωρίς υπηρεσία email η πλατφόρμα λειτουργεί πλήρως: οι γονείς παίρνουν απόδειξη στην οθόνη και οι εκπαιδευτικοί συνδέονται με τον κοινό κωδικό εκπαιδευτικών και τον ΑΜ/ΑΦΜ τους (ή με προσωπικό σύνδεσμο από τον διαχειριστή). Στο Netlify μπορεί να ενεργοποιηθεί αποστολή μέσω Brevo (μεταβλητές `BREVO_API_KEY`, `MAIL_FROM`)· προσοχή, οι διευθύνσεις `@sch.gr` δεν γίνονται δεκτές ως αποστολέας από τέτοιες υπηρεσίες.

- **Κωδικός διαχείρισης:** μακρύς, μοναδικός, μόνο στις ρυθμίσεις του Netlify ή στο `/etc/omiloi.env`. Ποτέ σε email, μηνύματα ή στο GitHub.
- **Secret key του Supabase:** μόνο στις ρυθμίσεις του Netlify.
- **Κοινός κωδικός γονέων:** αλλάζει κάθε χρονιά. Είναι γνωστός συμβιβασμός: όποιος ξέρει τον κωδικό και τα στοιχεία ενός μαθητή (ΑΜ και τέσσερα ονόματα) μπορεί να κάνει δήλωση για αυτόν. Γι' αυτό κάθε δήλωση έχει ιστορικό αλλαγών και κωδικό απόδειξης, που βλέπει ο γονέας.
- **Κρυφές διευθύνσεις** (`TEACHER_PATH`, `ADMIN_PATH`): δίνετε σε κάθε ομάδα μόνο τη δική της. Δεν αντικαθιστούν τους κωδικούς· αν διαρρεύσουν, αλλάξτε τις και ξαναδημοσιεύστε.
- **Κοινός κωδικός εκπαιδευτικών:** μόνο στους εκπαιδευτικούς. Μαζί με τον ΑΜ/ΑΦΜ ο καθένας βλέπει μόνο τους ομίλους του· αν αλλάξει ο κωδικός, όσοι είχαν συνδεθεί αποσυνδέονται.
- **Σύνδεσμοι εκπαιδευτικών:** προσωπικοί, ισχύουν 7 ημέρες· στέλνονται μόνο στον ίδιο τον εκπαιδευτικό.
- Υπάρχει όριο αποτυχημένων προσπαθειών σύνδεσης ανά διεύθυνση και ανά ΑΜ.
- **Αρχεία με στοιχεία μαθητών** (κατάλογοι, εξαγωγές, αποτελέσματα) δεν ανεβαίνουν ποτέ στο GitHub.

## 11. Για προγραμματιστές

| Φάκελος | Περιεχόμενο |
|---|---|
| [`platform/`](platform/README.md) | Η πλατφόρμα: σελίδες (`public/`), αλγόριθμος και API (`src/`), τοπικός server (`dev/`), server παραγωγής (`server/`), Netlify Function, tests |
| [`R/`](R/README.md) | Η κατανομή σε R (offline) |
| [`docs/`](docs/) | Εγχειρίδια |
| [`archive/`](archive/NOTE.md) | Τα scripts της προηγούμενης χρονιάς (μόνο για αναφορά) |

Τοπικά, με Node.js ≥ 20 και χωρίς εγκατάσταση πακέτων:

```sh
cd platform
npm run dev -- --demo    # δοκιμαστικό σχολείο: http://localhost:8888 (γονείς), /diaxeirisi-dev/ (διαχείριση, κωδικός admin)
npm test                 # tests
```

Σε κάθε αλλαγή τρέχουν αυτόματα (GitHub Actions): τα tests, η σύγκριση πλατφόρμας–R σε τυχαία σενάρια, και μια πλήρης διαδρομή σε browser (Playwright). Λεπτομέρειες: [platform/README.md](platform/README.md).
